# 天气看 7 天、按天选；从哪里进就看哪里

ADR 0010 的天气页顶部是一排地点按钮（我的位置 / 参考轨迹 / 正在看的轨迹 / 长按的点），只给 48 小时，逐小时一行一行往下列。用起来有三个问题：顶部那排按钮让人搞不清现在看的是哪里；出发前要看的往往是周末、三五天后，48 小时不够；纯列表不像天气 App，一眼看不出这一周哪天能走。

改为：

- **入口决定地点**：地图右上的天气按钮看我的位置，长按地图看那个点，轨迹详情顶栏右侧的天气按钮看这条轨迹沿途。天气页只有标题和关闭，不再切换地点。轨迹详情抽屉里的「沿途天气」一行去掉。
- **7 天、按天选**：和风 v7 逐小时最长 168 h，就取 7 天（今天从当前小时起）。页面从上到下是现在、7 天日期条（图标、最高 / 最低、降水量，有雷雨、强降水或大风加红点；低温在高处几乎天天有，只在数字上标红）、选中那天的气象图：参照 Windy 一类户外天气 App，横向滑动，天气图标、气温曲线、体感、降水柱、风向箭头和阵风对齐在同一时间轴上，夜间时段加底色。沿途天气的地点按钮写选中那天的最高 / 最低，红点也按那天算。
- **天气类型和风向**：服务端每小时多给 `sky`（晴、多云、阴、雾、雨、雪，雷阵雨仍由 `thunder` 标）和 `windDir`，和风取图标代码和 `wind360`，Open-Meteo 取 WMO 天气代码和 `wind_direction_10m`。推翻 ADR 0010「预报里没有云量，不判断晴天」那条：图标按天气类型画，夜里晴和多云换成月亮。

仍不估算到达时间（ADR 0009）。15 天先不做：和风 v7 第 8–15 天只有逐日预报，Open-Meteo 虽有逐小时但要混两个来源，等确实有人要再定。

## Consequences

- `POST /v1/weather` 一次最多 200 个点（原来 100）；一个地点 168 个整点仍只占 1 个网格配额。旧版服务端会拒绝 168 个点，**先部署服务端再发 App**。
- 我的位置的缓存文件变大到约 30 KB；旧缓存没有 `sky` / `windDir`，按原来的规则画图标，不画风向。
- 记录中的出行提醒仍只看当前位置未来 3 小时，不受影响。
