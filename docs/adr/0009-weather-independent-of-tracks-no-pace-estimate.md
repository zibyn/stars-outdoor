# 天气独立于轨迹，不再估算配速和到达时间

原来的「沿途天气」挂在轨迹详情里：按 Tobler 公式乘配速档（慢 / 中 / 快）估算到达沿线各点的时刻，取那个小时的预报，再推出「天黑前走不完」和参考轨迹条上的「预计到达」。这让天气和轨迹耦合得很紧：看天气要先打开一条轨迹，轨迹详情里塞着出发时间、配速档这些和轨迹本身无关的设置；而配速估算本身对负重、路况、队伍节奏都不准，算出的时刻反而容易误导人。

改为：**天气是某个地点的数据**（我的位置，或长按地图选的点），给未来 48 小时逐小时的气温、体感、降水、阵风、雷阵雨，加日出日落和官方预警；超过出行提醒阈值的数值标红。**不估算行进速度**，怎么走、几点能到由用户自己判断。入口是顶部栏的天气按钮（显示当前气温，有风险时加小红点），推翻了 ux-v2「没有独立天气页」那条。

同时，轨迹详情改为全屏查看：抽屉最低收到窄条、不会被拉没，窄条上显示「我在沿轨 x km 处 / 我离轨迹 x m」，不必设参考轨迹也能确认自己在哪；我的位置改成红点 + 白圈 + 朝向光束（主流地图的通用样式）。

## Consequences

- 去掉：配速档、出发时间、沿途取样、「天黑前走不完」、参考轨迹条和活动状态第二页的「预计到达」（那格换成当前海拔）、出行提醒横幅。
- 记录时的出行提醒改看当前位置未来 3 小时，和参考轨迹无关；循迹但不记录时仍没有提醒。
- 服务端 `POST /v1/weather` 不用改：同一位置 48 个整点只占 1 个网格配额。
- 旧版按轨迹缓存的天气文件（`filesDir/weather/`）在启动时删除；我的位置的预报缓存在 `weather-here.json`。
