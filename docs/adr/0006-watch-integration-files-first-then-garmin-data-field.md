# 手表对接：MVP 只靠标准文件，之后先做佳明 Connect IQ 数据栏

我们希望和佳明、高驰、颂拓、苹果表做双向深度集成：活动结束后，表的轨迹同步进 App；表上显示沿轨里程、队友、求助；活动中由表给手机提供定位。调研（#82，`research/watch-integrations` 分支）发现：
- 活动后云同步，三家都要求企业资质，中国区要另签协议。
- 高驰没有表端开发平台；颂拓 SuuntoPlus 没有文档化的与手机通信接口。
- 苹果表只配 iPhone，而我们 Android 优先。
- 只有佳明的 Connect IQ 数据栏能在原生徒步活动里双向通信，而且个人开发者可以上架，中国区有商店。

所以我们决定：

- **MVP 不新增任何对接。** 路线进表靠现有的 GPX 导出，三家都收，不加 FIT 路线导出。表的轨迹进 App，靠用户从表的 App 导出 FIT 或 GPX，再用现有的导入功能导进来。导入 FIT 时，从文件头读出厂商和型号，作为轨迹的来源标记（「来自 佳明 fēnix 7」）。表来的轨迹就是普通 **轨迹**，规则不变，不自动去重。
- **MVP 之后先做佳明 Connect IQ 数据栏**，不做完整的 Watch App，好让原生徒步活动照常记录。数据栏把表的位置和距离发给手机，并显示手机发来的几个数和一行提醒（沿轨里程、队友、求助、新消息）。它依赖用户手机上装着 Garmin Connect，由它做蓝牙中转。
- **活动后云同步等有了公司主体再做**：先申请佳明中国和颂拓中国。Health Connect 不需要资质，但是否带轨迹、国内无 GMS 的手机能否用都未核实，届时先做一次小验证。
- 高驰一直只靠文件，除非它开放表端平台；颂拓等有了与手机通信的接口再看；苹果表等 iOS App 立项后再做；国内手表（华为、小米、Amazfit）不在这次范围内。

这偏离了原来「活动后同步 > 表上显示 > 实时喂定位」的优先级：排在第一的一项被资质卡住，而佳明数据栏一次就覆盖了后两项。

## Consequences

- 数据栏的发送频率、蓝牙延迟和耗电都没有官方数字，开工前要先用真机做原型实测。中国版 Garmin Connect 能否让 SDK 连上，也要在实机上确认。
- 数据栏屏幕小、内存小，只放得下几个数：队友列表和回消息仍然回到手机上做。
