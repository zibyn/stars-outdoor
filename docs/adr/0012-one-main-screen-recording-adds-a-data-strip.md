# 只有一套主界面，记录时多一条数据窄条

ux-v2 按 [原型：整体交互模式对比](https://github.com/zibyn/stars-trail/issues/69) 选了「规划 / 活动分离」：记录中换一套布局，顶部深色大字数据，左侧队伍、分享位置、更多，底部暂停和标注两个大键，底栏隐藏。v3 的路径审查发现，这套分离让同一个入口在两种状态下位置不同（我的轨迹、离线地图、设置在记录中只能从「更多」抽屉进），而且「分享位置」和「共享位置」只差一个字。

改为（[决定：整体骨架的去留](https://github.com/zibyn/stars-trail/issues/131)）：

- **一套布局**：底栏（我的轨迹 / 队伍 / 开始 / 离线地图 / 设置）始终显示，记录与否入口都在原位。
- **记录时**：居中的开始键变成暂停；点暂停后弹出一条小栏「继续 / 按住结束」，底栏不变。底栏上方出现一条 **数据窄条**（一行大字，可上拉看更多），参考轨迹条并进窄条；同轨迹详情的「窄条 + 上拉」。惯用手一侧的标注圆键放大成带标签的大键。
- **去掉** 活动状态的队伍、分享位置、更多三个键：队伍走底栏；分享位置拆开，在队伍里用对话页「发我的位置」，不在队伍里点地图上的我的位置红点，出小抽屉「分享坐标 / 标注这里」。

参照 Strava 的记录页（数据和地图同时可见）。没有选记录时换成一条记录控制栏、把入口收进数据面板：入口位置固定比记录中少几个键更重要；戴手套的需求由放大的标注键和按住结束承担。

## Consequences

- 术语 **规划状态**、**活动状态** 在 v3 落地后作废，改说「记录中」。
- 地图上的抽屉打开时盖住底栏；记录中抽屉顶部保留一行只读数据，点一下收起抽屉。
- 地图比 v2 规划状态矮一条窄条（记录中）；窄条必须压到一行大字。
