# 现状审查：首屏按钮、文案、图标与核心路径

> 工单：[#63](https://github.com/zibyn/stars-outdoor/issues/63)（地图 [#61](https://github.com/zibyn/stars-outdoor/issues/61) 第 2 步"现状审查"）。只出报告，不改代码。
> 基线：`origin/main` @ `bee765c`（2026-09-29）。行号都是这个提交里的，路径相对 `app/src/main/java/dev/stars/outdoor/`。
> 术语以 `CONTEXT.md` 为准。"规划状态 / 活动状态"、按钮形式规则、语气要求取自 #61 的 Notes。
> 第 3 点（一键标注当前位置）和第 5 点（多轨迹叠加）的**实现影响评估**不在本报告里，由各自的工单承担。本报告只写这两点涉及的现状。

## 0. 先说结论（按影响排序）

1. **地图上没有"我"。** 首屏不画自己的位置，没有定位按钮，启动时相机固定在秦岭（`MainActivity.kt:320`，33.96, 107.77），不会移到用户所在位置。记录中也不画正在记录的轨迹，不显示距离和用时。spec §1.3-1（"启动即进地图并定位"）和 §2.1（右下角定位按钮）都没有做到。活动状态下，这是"一眼看懂"的最大缺口，也让"长按地图添加标注"几乎只能靠猜位置。
2. **首屏全是文字按钮，并且都挤在右上角一列。** 一共可能出现 13 个：菜单、图层、队伍、对话，加上菜单展开的 8 项和回正（`MainActivity.kt:472-500`），每个大约 43 dp 高，低于 spec 自定的 56 dp。展开菜单后这一列大约 600 dp 高，不能滚动；按返回键收不起菜单，会直接退出 App；点地图也收不起来。
3. **安全相关的动作藏得深。** 一键求助只在对话抽屉底部，要先点"对话"再长按"求助"，没加入队伍时根本没有入口（这是设计使然）。"分享坐标"分享的是长按选中的点，不是我当前的位置。队友**失联**只是地图上一行 11 sp 的小字（`MainActivity.kt:466-468`），不醒目。
4. **很多状态完全没有提示**：离线（全局）、GPS 无定位或信号弱、同步失败、自己的位置没有发出去（排队中）、电量低（只在队伍共享时、低于 10% 发一次通知）、记录时拒绝了定位权限（点"开始"后什么也不发生）、系统定位开关是关的。spec §1.3-4 允许的"离线中"提示也没有全局显示。
5. **离线时对话里打的字会丢。** 点"发送"后输入框立刻清空，发送失败只弹一条 toast（`Chat.kt:246`、`MainActivity.kt:1156`），文字没有排队重发。求助有 15 秒重试，但遇到非离线错误（比如登录失效）就停止，并提示"求助发送失败：登录已失效，请重新登录"（`MainActivity.kt:1179`）。
6. **叠加多条轨迹现在做不到。** 地图最多同时显示 2 条自己的轨迹：**参考轨迹**（蓝，6 dp）和正在打开详情的那条（橙，4 dp）。详情一关，第二条就消失了。详情轨迹的橙色 `#E4572E` 和周边路网里 OSM 路径的橙色 `#e8590c` 几乎一样，用户轨迹和参考层分不开。
7. **没有动画，也没有图标。** 所有面板都是瞬间出现、瞬间消失，相机也全部用 `setCameraPosition`、`fitCameraToBounds` 瞬移。项目不引入图标库；UI 上只有几个字符凑成的符号（✎ × ☑ ☐），通知里用的是 `android.R.drawable` 的系统旧图标，App 本身也没有设置启动图标。
8. **大多数点击区低于 48 dp，强光下对比度不够。** 主色绿 `#2F9E6E`、红 `#E4572E` 配白字的对比度只有 3.4 和 3.7，所有 12 sp 的灰色说明文字（`Color.Gray`）只有 3.5，都达不到 WCAG AA 的 4.5:1。首屏白色按钮没有描边和阴影，压在浅色地形图上时边界不清楚。
9. **文案本身大多平实、具体，语气接近要求**，主要问题有三个：
   - 活动状态用 toast 传达关键结果（2 秒就消失，戴手套、强光下容易错过）。
   - 同一件事有几种说法：停止共享 / 暂停共享 / 已停止共享；停止记录 / 结束（spec 里是"结束"）。
   - 规划状态直接暴露技术名词：WGS-84、MBTiles / PMTiles、GCJ-02、"进程"。

## 1. 首屏按钮表

首屏 = `MainActivity.setContent` 里的地图层（`MainActivity.kt:419-546`）。按钮是通用的 `MapButton`（`MainActivity.kt:1366-1368`：白底圆角 8 dp，内边距 12 dp，默认 14 sp 黑字，下间距 8 dp），实际高度大约 43 dp。

频率判断：**高** = 每次使用多次，**中** = 每次出行一两次，**低** = 偶尔，**—** = 这个状态下基本不用。

建议形式按 #61 Notes 的规则：高频且含义通用的动作用纯图标；不常用或含义可能模糊的用图标 + 2–4 字标签；安全相关的动作必须有文字并且醒目。这里只写形式，不写位置，布局由后续工单决定。

### 1.4 首屏缺少的按钮（开发者问题 2 / spec §2.1）

- **定位 / 回到我的位置**：没有。spec §2.1 写的是右下角定位按钮。
- **缩放**：没有按钮，只能双指缩放。单手戴手套时很难操作。
- **求助**：首屏没有，只能在对话抽屉里找到。
- **分享我的位置**：首屏没有。现在有两种近似做法：对话里点"位置"，把当前位置发给队友；或者长按地图，分享所选点的坐标。

## 2. 文案表

说明：
- **toast** 用的是 `Toast.LENGTH_SHORT`（`MainActivity.kt:1264`），大约 2 秒。
- 服务端的错误**不会原文显示**：客户端只读 `{"error": code}`（`OfflinePackages.kt:270`），再用本地映射表转成中文。没有进映射表的码一律显示兜底文案（比如 `invalid_request`、`image_not_found`、`photo_quota_exceeded`、`data_unavailable` 到了队伍页都变成"操作失败，稍后再试"）。
- 问题一栏对照的语气是"可靠、简洁、沉稳，像领队而非系统报错"；活动状态下要求文案极短。

### 2.5 文案的共性问题

- **活动状态靠 toast 反馈**：标注成功、没有定位、发送失败、保存失败都是 2 秒的 toast，没有常驻状态。
- **同一件事几种说法**：停止共享（CONTEXT）/ 暂停共享（通知）/ 已停止共享（成员行）/ 共享我的位置（开关）；停止（按钮）/ 停止记录（通知）/ 结束（spec）；"请稍候"和"稍后再试"混用；"点击查看"和"点开查看"混用。
- **系统腔**：兜底的"操作失败，稍后再试""下载失败，稍后再试""登录失败，稍后再试"；"检测到""进程"。
- **技术名词**：WGS-84、MBTiles / PMTiles、GeoJSON / PLT、GCJ-02 / BD-09、Photon。
- **好例子，可以当语气样板**："离线中：只能列出离线包内的轨迹"、"天黑前走不完：预计 17:40 到达终点，日落 17:25"、"发起人已结束行程，位置共享已停止"、"范围太大：单个离线包约 100 × 100 km 以内，请放大地图后再下载"。

## 5. 核心路径：现在的步骤与卡点

点击数只算 App 内的点击，不算输入文字；"系统"表示系统弹窗或选择器。

### 5.1 规划并保存路线

App **不能画路线**（spec §1.5 把"路线规划"列为不做），"规划"只有三种来源：

| 做法 | 步骤 | 点击数 |
|---|---|---|
| 从文件导入 | 菜单 → 我的轨迹 → 导入… → 系统文件选择器（选文件）→（文件里有多条时：勾选 → 导入 N 条）→ 自动打开轨迹详情 | 3 + 选择器 ≥1（+1） |
| 从微信 / QQ 打开 | 在微信里"用其他应用打开" → 选 Stars Outdoor → 自动导入并打开详情 | App 外 2–3 次，App 内 0 |
| 从周边路网保存 | 图层 → 周边路网（开）→ 关掉图层抽屉（返回键或再点图层）→ 点地图上的线 → 保存到我的轨迹 | 5 |

保存以后出发前的准备：设为参考轨迹（1）、沿此轨迹下载离线地图（1）、出发时间（系统日期 + 时间，2–4）、配速档（1）。都在详情面板里完成。

**卡点**
- 不能画路线，也不能改已有的路线。
- 从周边路网保存下来的轨迹以线名命名，没有线名就叫"平台轨迹""徒步线路"，重名以后很难分；保存只有一条 toast，不能直接跳过去看。
- 周边路网抽屉和轨迹详情都**没有关闭按钮**，只能按返回键。
- 计划轨迹的用时显示"0:00"。
- 轨迹详情会盖住"开始"。
- 我的轨迹列表没有距离、日期、缩略图，为空时没有任何提示。

### 5.2 叠加多条轨迹对比（第 5 点的现状）

- **现在最多同时显示 2 条自己的轨迹**：**参考轨迹**（`#3B7DD8`，6 dp，`MainActivity.kt:325`）和正在打开详情的那条（`#E4572E`，4 dp，`:329`）。
- 步骤：菜单 → 我的轨迹 → 选 A → 设为参考轨迹 → 返回（详情关闭）→ 菜单 → 我的轨迹 → 选 B，一共 **7 次**。只有 B 的详情开着时才能对比，而详情面板最高 560 dp，要占掉屏幕下半部分。第三条轨迹没有办法加上去。
- 自己的轨迹不能逐条开关，不能配色，也没有图例。
- 周边路网（`assets/style.json:270-361`）的样式：OSM 路径橙 `#e8590c`、徒步线路 `#c2255c`、平台轨迹 `#0b7285`，都是 3 px、80% 不透明度；公开轨迹紫色，35% 不透明度。**详情轨迹的橙色和 OSM 路径的橙色几乎一样**，线宽也只差 1 dp，视觉上看不出用户轨迹在前、路网在后。

### 5.3 出发开始记录

- **第一次**：开始（1）→ 系统定位权限（1–2）+ 通知权限（1）→ 电池引导弹窗（点"知道了"1 次；如果照着设置，要跳出 App 走 3 步以上）→ 开始记录。
- **以后**：开始（1）。
- 如果要循迹，出发前还要先设参考轨迹（菜单 → 我的轨迹 → 选轨迹 → 设为参考轨迹，4 次）。

**卡点**
- 开始记录以后，地图上**看不到自己，也看不到正在记的线**，没有距离、用时、GPS 状态。唯一的变化是按钮从绿"开始"变成红"停止"，上面多了"暂停记录"和"标注当前位置"。
- 拒绝定位权限以后没有任何提示（`MainActivity.kt:215-222`）。
- "停止"点一下就生效、不能撤销，还和"开始"在同一个位置，戴手套误触的风险高。
- 电池引导在正要出发时弹出，内容很长。

### 5.4 活动中标注当前位置（第 3 点的现状）

| 场景 | 步骤 | 点击数 |
|---|---|---|
| 记录中、没暂停 | 标注当前位置 → toast | **1** |
| 记录已暂停 | 按钮被隐藏：要么先继续记录再标注（2），要么走下面这种 | 2 |
| 没在记录（比如只是在队伍里共享位置） | 长按地图上**估计的**位置（地图上没有"我"）→ 添加标注 → 进入标注编辑整页 → 完成或返回 | 3（长按 1 + 点 2） |

**卡点**
- 一键标注只在"记录中并且没暂停"时出现。
- 没有位置点，所以长按标注的误差大，这就是开发者说的问题 3。
- 定位超过 30 秒就只弹 toast，不会等到下一个定位点再标。
- 长按标注会直接打开整页编辑器，把地图挡住。

### 5.5 查看队友位置

| 场景 | 步骤 | 点击数 |
|---|---|---|
| 已在队伍中，看全貌 | 队友圆点一直显示在地图上，但相机不会自动框住全队，要自己拖动或缩放地图去找 | 0 次点击 + 手势 |
| 已在队伍中，找某个人 | 队伍 · N 人在线 → 点成员行 → 回到地图并定位到他 | 2 |
| 第一次组队（已登录） | 菜单 → 队伍 → 输入队伍码 → 加入队伍 → 系统定位权限 | 3 + 输入 + 系统 1–2 |
| 第一次组队（没登录） | 菜单 → 队伍 → 登录页：输入手机号 → 获取验证码 → 输入验证码 → 登录 → 自动进入队伍页 → 输入队伍码 → 加入队伍 → 系统权限 | 5 + 3 次输入 + 系统 1–2 |

**卡点**
- 地图上的队友圆点点了没反应。
- **失联**标签是 11 sp 小字，不醒目。
- **停止共享**的人会从地图上彻底消失。
- 队伍页是整页，看成员时看不到地图。
- 每个人的方位只在队伍页以文字显示（"1.2 km 东北"）。
- 队友电量低在地图上看不到。

### 5.6 离线状态下继续使用

**出发前**
- 菜单 → 下载当前视野（2 次）：不确认，不预估大小，名称自动生成；视野太大时报"范围太大"。
- 或者轨迹详情 → 沿此轨迹下载离线地图（1 次）。
- 下载没有进度，只有开始和结束两条 toast，离线地图页里显示"正在下载…"。

**没有网络时**

| 功能 | 表现 |
|---|---|
| 地形底图（有离线包的区域） | 正常 |
| 卫星 / 标准底图 | 没缓存的区域一片空白，**没有提示** |
| 搜索 | 只显示离线结果，有小字说明 |
| 周边路网 | 只列出离线包里的线，有说明 |
| 天气 | 显示缓存和它的更新时间 |
| 记录轨迹 | 正常（spec 的可靠性红线） |
| 队伍 · 自己的位置 | 在内存里排队，**不提示**；进程被杀就丢了（`RecordingService.kt:95` 的 ponytail 注释） |
| 队伍 · 队友 | 圆点逐渐变淡，最后显示失联；分不清是谁那边没信号 |
| 对话 | 发送失败，**打的字丢失** |
| 求助 | 每 15 秒重试，有说明；App 被关掉就停止 |
| 同步 | **没有任何提示**，联网后自动补上 |

**卡点**：地图上没有全局的"离线中"状态，用户没法判断现在哪些功能还能用。

## 6. 「上一条轨迹」按钮（开发者问题 4）

**它做什么**：不在记录时，它出现在"开始"大按钮上方（`MainActivity.kt:530-536`，和"暂停 / 继续记录"是同一个控件）。点一下会打开 `TrackDb.lastEndedTrack()`（`TrackDb.kt:210-216`）返回的那条轨迹的**轨迹详情**。这个查询取的是 `ended_at` 不为空、至少有一个点、**id 最大**的那条轨迹。如果库里没有这样的轨迹，就弹 toast "还没有记录过轨迹"。

**它是怎么来的**：最早的骨架提交 `c30f848` 里，这个位置是"导出上一条轨迹 GPX"，那时候还没有我的轨迹列表，也没有详情页，它是记录完以后导出的唯一出口。后来 `a13de88` 加了轨迹详情，就把它改成了"上一条轨迹 → 打开详情"，一直留到现在。

**什么时候出现**：只要不在记录就一直显示，包括从来没记录过的新用户。记录中这个位置换成"暂停记录 / 继续记录"。

**中立地记几点现状（去留由 [#68](https://github.com/zibyn/stars-outdoor/issues/68) 决定）**：
- **名字和行为对不上**：它按 id 取最新的一条，所以**导入**的轨迹、从周边路网**保存**的计划轨迹、**同步拉下来**的轨迹都会被当成"上一条"。导入一个 GPX 以后点它，打开的是那个 GPX，不是上次自己记录的。空库时的 toast "还没有记录过轨迹"也就不准确。
- **同一个位置在两种状态下是两种性质的动作**：不在记录时它是"浏览历史"（规划或回顾时用），记录中是"控制记录"（活动时用）。按钮外观完全一样，只有文字变了。
- **它是首屏除了"开始"以外唯一的底部按钮**，占的是拇指最容易够到的位置，但使用频率低：记录完以后大约用一次，平时用菜单 → 我的轨迹也能到。
- 它现在能满足的需求是"刚走完，想马上看看这一趟"。停止记录以后 App 不会自动打开刚记录的轨迹（停止只在服务里结束轨迹，界面上没有后续）。
