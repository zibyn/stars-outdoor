# 调研：云海可能性的判定方法

调研日期：2026-10-06。对应问题：#240（属于 #237 专业户外天气）。术语见 `CONTEXT.md` 的 **云海**：观景点海拔高于低云的云顶，头顶少云；**天气** 给出高 / 中 / 低三档。现状见 `server/weather.go`：和风给逐小时数据和预警，Open-Meteo 补阵风和格点海拔。

**来源说明**
- 只用一手来源：期刊论文原文、气象部门的专利和官网文章、服务商的 API 文档或 OpenAPI 定义。
- 方括号里是来源编号，见文末。没能打开原文、只看到摘要的，标 **仅摘要**。
- 服务商字段是 2026-10-06 读到的版本；Open-Meteo 的字段名用一次实际请求核对过（§4.1）。

## 1. 结论

- **云海的物理条件很一致**：低层湿（接近饱和）、上层干、中间有逆温或接近等温的稳定层，风弱。云顶基本就是逆温层底。观景点要在云顶之上，而且不在云里 [B1][J1][M1]。
- **国内业务和研究都靠气压层廓线**，不靠单层的「低云量」：
  - 北京市气象服务中心只用各气压层相对湿度做模糊逻辑，准确率 94.5%、F1 0.81 [B1]。
  - 重庆市气象局的专利用各层相对湿度和位势高度，按观景点海拔把大气切成「山下 / 山顶 / 高空」三段，算云量后分档 [P1]。
  - 黄山气象管理处看 700、850、925 hPa 的湿度、风速、气温，给 10% 到 90% 五档概率 [C1]。
- **只靠标准字段做不到**。`cloud_cover_low` 是一整段（Open-Meteo 写的是 0–3 km [O1]，ECMWF 是气压大于 0.8 倍地面气压的那几层，约 2 km 以下 [E1]）的合计，分不出云在观景点上面还是下面。观景点在 1500 m、云在 1000 m 和云在 2000 m，这个字段一样。云底高度（ECMWF `cbh`）只给最低云层的底，不给顶 [E2]，判不了云海。
- **结论：必须用气压层廓线**（相对湿度 + 位势高度，最好加气温）。Open-Meteo 免费提供，和现在的接法同一个请求就能拿到；和风没有。
- 下面 §5 给出能直接实现的三档规则草案，阈值从 [B1] 的统计和 [P1] 的公式里推出来，需要上线后按实况校准。

## 2. 云海是怎么形成的

- **「下湿上干」+ 逆温**：北京 46 个高山云海个例（ERA5 单点插值）中，850 hPa 以下各层相对湿度中位数都在 87% 以上，1000、950、925 hPa 达到 93%；850 hPa 以上中位数都小于 60%，500 hPa 小于 30% [B1]。
  - 原文：「"下湿上干"和逆温是云海的典型垂直配置」[B1]。
  - 950–850 hPa 的气温递减率中位数约 0.3 °C/100 m，「明显小于正常的对流层大气层结」；再分析资料垂直分辨率不够，没直接显示逆温 [B1]。
  - 海陀山梯度站 16 个云海个例全部有逆温，相邻站最强 8 °C；逆温层里相对湿度随高度迅速减小，最大差 50% [B1]。
- **风弱**：北京个例中 800 hPa 及以下风速多小于 10 m/s；文献综述中近地面多小于 3 m/s，「避免湍流破坏云层结构」[B1]。
- **无云海的反例**：大风、高温时低层相对湿度小于 50%；降水时高层相对湿度达 100%。「低层过小或高层过大的相对湿度导致出现云海的概率极小」[B1]。
- **天气形势**：
  - 北京分为前倾槽（雨后，43%）、高压脊（可连续多日早晨出现，30%）、偏东风（秋冬，27%）三型 [B1]。
  - 日本阿尔卑斯：大范围云海多在清晨；半数以上目标区同时出现云海的日子里，67% 与高压下沉逆温有关 [J1]。
  - 英国 MWIS（山地天气服务）：高压带来下沉增温，低层水汽被困在逆温层下，上方变干；系统移动慢最有利 [M1]。
- **时段**：梵净山 2020 年 85 天有云海，集中在 2–4 月凌晨 4 点到上午 8 点（FY-4A 云顶高度识别）[F1，仅摘要]。北京的高压脊型也是后半夜到早晨出现、日出后消散 [B1]。

## 3. 现有的云海预报方法

| 方法 | 输入 | 规则 | 来源 |
|---|---|---|---|
| 指标叠套（黄山冬半年） | 925–700 hPa 湿度差、700 hPa 24 h 变湿、850–700 hPa 温差、925 hPa 24 h 变温、850 hPa 风速、850 hPa 24 h 变高等 16 项 | 每项落在区间内记 1 分，累计 ≥ 13 判有云海 | [P1] 背景技术引丁国香等 2019 |
| 黄山气象管理处 | 700、850、925 hPa 湿度、风速、气温；降水、风力 | 五档：10% 无云海 / 20% 可能性较小 / 50% 一般 / 70% 较大 / 90% 很大 | [C1] |
| 北京模糊逻辑 | 1000–400 hPa 共 10 层相对湿度 | 见下方公式，P > 0.7 判有云海 | [B1] |
| 重庆网格化（专利） | 各层相对湿度、位势高度；地形高度 | 见下方三段法 | [P1] |

**北京公式** [B1]：`P = L850·L800 + (1 − L850·L800) × mean(L1000, L950, L925, L900) × mean(L700, L600, L500, L400)`。Li 是各层相对湿度的隶属度，由本地个例统计出来（850 hPa 的隶属度曲线在论文图 11），不能直接搬到别处。850 和 800 hPa 是「下湿」转「上干」的关键层，所以权重放大；海拔因素已经含在隶属度里，只适用于北京这几个山头。

**重庆三段法** [P1]（重庆市气象局，CN112987131B）：
1. 每层云量用 Slingo 公式：`N = ((H − Hc) / (1 − Hc))²`。Hc 是临界相对湿度：700 hPa 以下、500 hPa 以上取 0.8，700–500 hPa 取 0.65。H ≤ Hc 时 N = 0。
2. 用位势高度和观景点的地形高度找三段：
   - **山顶云量**：高于地形高度、离它最近的那一层的云量；
   - **高空云量**：山顶层以上所有层的最大云量；
   - **山下云量**：山顶层以下所有层、周边格点的云量平均。
3. 判定：山顶云量 ≥ 0.4 → 无云海；山下云量 ≤ 0.1 → 无云海；否则高空云量 > 0.4 是「阴天云海」，< 0.1 是「晴天云海」，之间是「多云云海」。概率 `P = (1 − C山顶) × C山下`。

重庆三段法不依赖本地个例，只要有分层的相对湿度和位势高度就能算，最适合我们（观景点由用户任意选，没有本地样本）。

**换算一下（自己算的）**：Hc = 0.8 时，N = 0.1 对应 RH ≈ 86%，N = 0.4 对应 RH ≈ 93%。和北京统计的「云海时低层 RH 中位数 87%～93%」[B1] 对得上。所以 0.1 / 0.4 这两档阈值有两个独立来源互相印证。

## 4. 服务商能给什么

| 字段 | Open-Meteo（免费，现已接入） | meteoblue（商用） | 和风（现主力） |
|---|---|---|---|
| 分层相对湿度 | `relative_humidity_{level}hPa`，19 层 1000–30 hPa [O1] | Relative Humidity Profile 包（按离地高度）[MB1] | 无 [Q1] |
| 层的海拔 | `geopotential_height_{level}hPa`，「可用来得到正确的海拔」[O1] | Atmospheric Profile 包 [MB1] | 无 |
| 分层气温（判逆温） | `temperature_{level}hPa` [O1] | Atmospheric Profile 包 | 无 |
| 分层云量 | `cloud_cover_{level}hPa`，「由相对湿度近似」[O1] | Cloud Cover Profile 包，按气压层 [MB1] | 无 |
| 低 / 中 / 高云量 | `cloud_cover_low/mid/high`，0–3 / 3–8 / 8 km 以上 [O1] | `lowclouds` `midclouds` `highclouds` [MB1] | 只有总云量 `cloudCover` [Q1] |
| 边界层高度 | `boundary_layer_height`；ECMWF 接口只在 IFS HRES 有 [O2] | `boundarylayerheight`：「Boundary layer height (Layer with inversion)」[MB1] | 无 |
| 云底高度 | 文档未列 | 只有对流云的 `convectivecloudbase_pressure` [MB1] | 无 |
| 雾概率 | 无 | `fog_probability` [MB1] | 无 |

各模型的气压层数不同，垂直分辨率直接决定能不能分出云顶：
- Open-Meteo 通用接口 19 层，低层有 1000/975/950/925/900/850/800/700 hPa，间隔约 200–500 m [O1]；
- ECMWF 接口只有 1000/925/850/700 hPa 这几层低层，间隔 700–1500 m [O2]；
- CMA GRAPES 接口 30 层 [O3]。
- 北京论文也说 ERA5 的垂直分辨率「对山顶上下高度关键层次的相对湿度刻画不够精准」[B1]。

### 4.1 实际请求核对

2026-10-06 对黄山（30.13N, 118.17E）请求 Open-Meteo `/v1/forecast`，默认模型：
- `relative_humidity_925hPa`、`geopotential_height_925hPa`（864 m）、`geopotential_height_850hPa`（1571 m）、`cloud_cover_low`、`boundary_layer_height` 都能拿到；
- 返回的格点 `elevation` 是 1466 m，比光明顶（约 1860 m）低约 400 m。

所以判定时**用观景点的实际海拔**，不要用格点海拔。

## 5. 可实现的规则草案（高 / 中 / 低）

按小时算，对每个观景点（海拔 `zv`，用户点选的地点或地图 DEM 海拔）。

**输入字段**（全部来自 Open-Meteo 同一次 `/v1/forecast` 请求）：
- `relative_humidity_{p}hPa`、`geopotential_height_{p}hPa`、`temperature_{p}hPa`，p ∈ {1000, 975, 950, 925, 900, 850, 800, 700, 600, 500}，共 30 个逐小时序列；
- `cloud_cover_mid`、`cloud_cover_high`（头顶少云的辅助判断）；
- `precipitation`、`wind_speed_{p}hPa`（可选，用于一票否决）；
- 返回的 `elevation`（格点地面海拔 zg），用来丢掉地面以下的层。

**步骤**：
1. 丢掉 `geopotential_height < zg` 的层（地面以下是外推值）。
2. 每层云量 `N = clamp((RH − Hc) / (1 − Hc), 0, 1)²`，Hc：700 hPa 以下 0.8，700–500 hPa 0.65 [P1]。
3. 三段（以观景点为界，比照 [P1]）：
   - **C顶**：把 RH 按高度线性插值到 `zv`，再用公式换成云量（观景点是否在云里）；
   - **C下**：高度在 `zv − 100 m` 以下各层 N 的最大值（专利用平均；单点取最大，以免一层厚云被干层平均掉）；
   - **C上**：高度在 `zv + 300 m` 以上、到 500 hPa 为止的最大 N，再和 `cloud_cover_mid`、`cloud_cover_high` 取最大，换成 0–1。
4. 稳定层（加分项）：`zv` 上下相邻两层的气温递减率 ≤ 0.3 °C/100 m，或出现逆温 [B1]。
5. **分档**：
   - **低**（任一满足）：C下 ≤ 0.1（低层 RH 不到约 86%）；或 C顶 ≥ 0.4（观景点在云里）；或该小时 `precipitation` > 0；或观景点附近层风速 ≥ 10 m/s [B1]。
   - **高**：C下 ≥ 0.4（低层 RH ≥ 约 93%）且 C顶 < 0.1 且 C上 < 0.4 且有稳定层。
   - **中**：其余情况。对应专利里的「多云 / 阴天云海」和湿度达标但不够稳的情形。
6. 同时把用来判断的数据交给前端：估算的云顶高度（C下 ≥ 0.1 的最高一层的位势高度）和 C上，对应 `CONTEXT.md`「同时给出用来判断的云层高度和云量」。

**说明和局限**
- 阈值是初值：0.1 / 0.4 有 [P1] 和 [B1] 两个来源，0.3 °C/100 m 和 10 m/s 来自 [B1] 的北京统计。上线后需要收集用户反馈或山顶摄像头实况来校准。
- 观景点上下 300 m 以内，靠两层插值分不清云顶，结果偏保守。
- 没用边界层高度。Open-Meteo 的 `boundary_layer_height` 是离地高度，地形起伏大的地方很难换算到观景点；而且 ECMWF 接口只有 IFS HRES 有 [O2]。可以以后作为「云顶 ≈ 格点海拔 + 边界层高度」的旁证再加。
- 和风只有总云量和地面湿度，**判不了云海**，必须接一家有气压层廓线的服务商。Open-Meteo 已经接入，零成本；它的气压层云量本身也由相对湿度近似 [O1]，和本规则的做法一致。
- 云海多在清晨（§2），前端可以把日出前后几个小时突出显示，规则本身不按时段区分。
