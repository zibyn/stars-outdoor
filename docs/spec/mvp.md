# Stars Outdoor MVP 规格

> 状态：定稿待评审（2026-09-27）。术语以仓库根目录 [`CONTEXT.md`](../../CONTEXT.md) 为准。
> 每条结论都附有对应决策工单的链接，想了解"为什么这样定"就去翻工单；全部决策的索引见 [Wayfinder 地图](https://github.com/zibyn/stars-outdoor/issues/1)。

## 1. 概述

### 1.1 目标

一个 **无广告、打开即用** 的户外地图 Android App。主要服务中国大陆徒步者，同时能用来规划海外经典线路。核心价值：
- 离线地图（中国）
- 可靠的轨迹记录
- 临时 **队伍** 共享位置
- **沿途天气** 与 **出行提醒**
- **周边路网**

### 1.2 平台与分发

- Android 优先，基于 MapLibre Compose（锁定 0.18.x），架构上为 KMP / iOS 保留余地。
- 第一版只通过 **GitHub Release** 发布 APK，不上架国内应用商店，也暂不上 Google Play。App 暂不开源。

### 1.3 产品原则（可逐条验收）

[决定：交互原则与信息架构](https://github.com/zibyn/stars-outdoor/issues/8)

1. **首屏只有地图**：启动即进地图并定位；没有开屏、信息流、商城或推广位。
2. **零打扰**：没有广告、评分弹窗、"新功能介绍"弹窗；权限在第一次用到时才申请。
3. **免登录**：地图、标注、轨迹、离线地图都不需要账号。只有 **队伍** 和云同步需要登录。
4. **离线优先**：没网时任何界面都不白屏、不报错，最多提示"离线中"。
5. **记录可靠**：切后台、锁屏、没网都不能中断轨迹记录（可信度红线）。
6. **戴手套可用**：关键按钮 ≥ 56dp，放在下半屏拇指区。
7. **数据归用户**：轨迹默认私有，界面明示；导入导出用标准格式，导出不丢标注。

### 1.4 公开承诺（写在"关于"页）

[决定：成本与可持续模式](https://github.com/zibyn/stars-outdoor/issues/13)

- **永不放广告。**
- **核心功能永久免费**：地图、离线地图（中国）、轨迹记录与导入导出、标注、队伍、沿途天气与出行提醒、周边路网。
- 将来如果收费，只针对新增、且有明确额外成本的功能（如海外离线地图、高清卫星图）。维持方式为免费 + 自愿捐赠，捐赠不解锁任何功能。

### 1.5 不在 MVP 范围

快速匹配组队、AI 出行建议、iOS 正式版、海外离线地图、国内应用商店上架、Google Play / 官网下载页 / F-Droid、长期固定群组、海外手机号登录、个人配速自动校准、真 3D 地形、路线规划 / 到出口的导航。

## 2. 功能

### 2.1 主界面与信息架构

[决定：交互原则与信息架构](https://github.com/zibyn/stars-outdoor/issues/8)、[原型：主界面可点击草图](https://github.com/zibyn/stars-outdoor/issues/16)（原型：`prototype/main-screen` 分支）

- **布局**：全屏地图 + 浮动按钮 + 底部抽屉，没有底部 Tab 栏。
- **常驻按钮（≤ 4 个）**：
  - 左上：菜单
  - 右上：图层
  - 右下：定位
  - 底部中间：大按钮，开始 / 暂停 / 结束记录
- **队伍按钮**：未加入队伍时放在菜单里；加入后常驻显示，带在线人数和未读数。
- **临时控件**：进入 3D 后，图层按钮下方出现指南针（引擎自带），点击回正并退出 3D。记录中，大按钮旁出现"标注当前位置"。这两个都不计入常驻上限。
- **菜单抽屉**：顶部是搜索；下面分为 我的轨迹 / 标注 / 离线地图 / 设置 四页。
  - 我的轨迹：搜索、排序（默认最近）、导入；每条显示缩略图、距离、爬升、日期，以及私有 / 公开 / 计划状态。
- **长按地图**：弹出卡片，提供 添加标注 / 测距 / 复制坐标 / 分享坐标（发给救援人员）。
- **风险横幅**：**参考轨迹** 有 **出行提醒** 时，地图顶部显示一条可关闭的横幅。

### 2.2 地图与图层

[决定：地图数据源与离线地图方案](https://github.com/zibyn/stars-outdoor/issues/9)、[调研：MapLibre Compose 3D 地形可行性](https://github.com/zibyn/stars-outdoor/issues/17)

**底图**用三张卡片切换：

| 卡片 | 国内 | 海外 | 离线 |
|---|---|---|---|
| **地形**（默认） | 自托管 Protomaps 矢量底图 + 山体阴影 + 分层设色 + 等高线 | OpenFreeMap 在线底图（MVP 不叠加山体阴影和等高线） | ✅（仅中国） |
| **卫星** | 天地图影像 | 天地图全球影像，注明"海外影像精度有限" | ❌ 仅在线 |
| **标准** | 天地图矢量 | OpenFreeMap | ❌ 仅在线 |

- **叠加开关**：等高线、山体阴影、3D 地形（2.5D）、周边路网、队伍成员。
- **等高线**：等距 20 m，计曲线 100 m。z12 只显示计曲线，z13 起显示全部；计曲线标注高度。
- **3D**：做 **2.5D**，即倾斜视角（最大 60°）+ 山体阴影 + 分层设色。真 3D 地形的引擎能力尚未合入，不做。进入方式：双指下拖，或打开图层里的"3D 地形"开关。
- **坐标系**：全链路 WGS-84（天地图 CGCS2000 视同 WGS-84），不接入任何 GCJ-02 / BD-09 图源。
- **署名**：地图上显示"© OpenStreetMap contributors"等所需署名。

### 2.3 离线地图

[决定：地图数据源与离线地图方案](https://github.com/zibyn/stars-outdoor/issues/9)、[任务：样例山区离线包体积实测](https://github.com/zibyn/stars-outdoor/issues/21)

- **范围**：只覆盖中国。对海外区域请求离线时提示"该地区暂不支持离线"。
- **下载方式**：在图层菜单里框选当前视野下载，或在轨迹详情里"沿此轨迹下载"（按缓冲带）。
- **包内容**：
  - 底图 PMTiles
  - DEM PMTiles（z0–11，用于山体阴影和分层设色）
  - 等高线 PMTiles（z12–14，z15 由引擎放大显示）
  - 徒步线路 GeoJSON（每条完整保留，供"经过这里的轨迹"保存或设为参考轨迹）
  - 平台轨迹 GeoJSON
  - 该区域的 SQLite 地名索引
  - 该区域 **公开轨迹** 的快照
- **体积参考**：50 km 见方的山区约 20–25 MB。
- **限额**：单个包的范围 ≤ 约 100 × 100 km；每台设备每天下载 ≤ 1 GB（匿名可用）。
- **字形**：包含 CJK 的 Noto Sans Regular 字形约 34 MB，属于一次性资源，不放进各个区域包。
- **管理**：在"菜单 → 离线地图"查看占用空间、删除、更新。服务端有新版本时显示"可更新"标记，不弹窗。
- **用户导入**：可以导入自己的 MBTiles / PMTiles 文件（"菜单 → 离线地图 → 导入"）。

### 2.4 标注

- 长按地图可以添加 **标注**。
- 记录中点"标注当前位置"：**一键先存坐标**，名称和照片可以事后补。语音备注不做。
- 标注可附文字和照片。导入文件中的航点会成为这条轨迹下的标注。

### 2.5 轨迹记录

[决定：离线记录与云同步规则](https://github.com/zibyn/stars-outdoor/issues/26)、[决定：队伍位置共享的上报与耗电策略](https://github.com/zibyn/stars-outdoor/issues/23)

- **采样**：每 5 s 或每移动 10 m 取一个点，以先到者为准。
- **前台服务**：与队伍位置共享合并为同一个前台服务。通知栏只常驻一条通知，带「暂停共享」「停止记录」按钮。
- **可靠性**：
  - 每个点采到后立即写入本地数据库。
  - 进程被杀或崩溃后，下次打开时提示"检测到未结束的记录：继续记录 / 结束并保存"。
  - 支持暂停和继续，一条轨迹可以由多段组成。
  - 第一次开始记录时，按手机品牌（小米、华为、OPPO、vivo 等）引导关闭电池优化，只提示这一次。
- **不可变**：结束记录后轨迹点不可修改，之后只能改属性（名称、描述、公开状态、坐标纠偏）。
- **轨迹详情**：显示统计（距离、爬升、用时）、海拔剖面、沿途天气区块，以及"设为参考轨迹""沿此轨迹下载离线地图"两个操作。

### 2.6 导入与导出

[决定：轨迹导入导出格式与互通](https://github.com/zibyn/stars-outdoor/issues/22)

- **导入格式**：GPX 1.1、KML / KMZ（包括奥维导出的 `.ovkml` / `.ovkmz`）、FIT（使用 Garmin 官方 Java SDK）、GeoJSON、PLT。不支持 TCX。**全部在客户端解析。**
- **入口**：
  - 菜单 → 我的轨迹 → 导入
  - 系统分享和"用其他应用打开"，例如从微信、QQ 收到的文件
- **多要素**：一个文件含多条轨迹时，先让用户勾选再拆开导入；GPX 的 `rte` 导入为"计划"轨迹。
- **坐标纠偏**：默认按 WGS-84 解析。轨迹详情里有"坐标纠偏"开关，可选 GCJ-02（高德、腾讯）或 BD-09（百度），实时预览效果，只对中国境内的坐标生效。
- **大小**：单个文件 ≤ 50 MB；原始点全部保留，显示时抽稀。
- **导出**：
  - 默认 GPX 1.1（含时间、海拔，以及标注的名称、描述、时间）；也可以导出 KML。
  - 标注带照片时，打包成 `.zip`（GPX + 照片文件夹）。
  - 通过系统分享面板发送。

### 2.7 循迹与偏离提醒

- 选一条轨迹设为 **参考轨迹**。偏离超过阈值（默认 50 m）时触发 **偏离提醒**：震动 + 通知。
- 不做逐向导航，不做路线规划，也不做路网吸附。

### 2.8 周边路网

[决定：周边路网数据方案](https://github.com/zibyn/stars-outdoor/issues/12)、[ADR 0002](../adr/0002-ugc-separate-from-osm.md)

周边路网由 **三个独立图层** 组成，互不合并，在图层菜单里用一个"周边路网"开关统一控制：

1. **OSM 路径与徒步线路**
   - 山路和小径复用底图要素，打开开关时加粗高亮。
   - **徒步线路**（`route=hiking|foot`）单独做成 GeoJSON，随底图更新，并进入离线包。
2. **公开轨迹**
   - 数据来自 PostGIS。z11 起在线显示，离线时使用包内快照。
   - z12 以上画成细的半透明线，重叠越多颜色越深。
3. **平台轨迹**
   - 来自香港渔护署郊野公园远足径、台湾林业保育署自然步道，注明来源。

**交互**：点击地图弹出"经过这里的轨迹"列表，可以把某条设为参考轨迹，或保存到我的轨迹。

**公开规则**：
- 轨迹默认私有，需要逐条公开。
- 公开时自动隐藏起点和终点各 200 m 的范围。
- 可以随时撤回公开。
- 查看别人的公开轨迹不需要登录，自己公开轨迹需要登录。

**应急**：只做可视化，可以配合测距量出到道路或村庄的直线距离。不做到出口的路线规划。

### 2.9 沿途天气与出行提醒

[决定：天气平台与出行提醒规则](https://github.com/zibyn/stars-outdoor/issues/11)

- **数据源**：主源是和风天气（1 km、逐小时、最长 240 h）加上它的预警接口；备用源是 Open-Meteo。**所有请求都经后端代理**，客户端不直连天气平台。
- **预计到达时间**：按 Tobler 徒步公式计算，再乘以 **配速档**（慢 / 中 / 快）。出发时间默认"现在"，可以修改。
- **取样**：沿轨迹每 1 h 或每 5 km 取一个点（取更密的那个），最高点、终点、出发点一定要取。
- **出行提醒 v1**（按到达各点的那个小时判断）：

| 提醒 | 触发 |
|---|---|
| 雷暴 | 天气现象为雷阵雨类，或区域有雷电 / 强对流预警 |
| 强降水 | 小时降水 ≥ 8 mm |
| 大风 | 阵风 ≥ 17.2 m/s；在山脊或最高点再提示一次 |
| 低温 | 体感温度 ≤ 0°C |
| 天黑前走不完 | 预计到达终点晚于日落前 30 min（日落时间在本地计算） |
| 官方预警 | 途经区域的任何官方预警原样转发 |

- **海拔修正**：温度按 −0.65°C / 100 m 修正（轨迹点海拔与网格海拔之差）。
- **离线**：设为参考轨迹或下载离线包时，把天气一起缓存。离线时显示"预报更新于 X 小时前"，超过 12 h 置灰。
- **提醒时机**：打开 App、设为参考轨迹时计算一次；在记录或循迹期间，只要有网，每 2 h 刷新一次，发现新风险就发本地通知。

### 2.10 搜索

[调研：地名/山峰搜索数据源（含离线）](https://github.com/zibyn/stars-outdoor/issues/18)

- **入口**：菜单抽屉顶部。
- **搜索内容**：地名、山峰、景点、坐标（十进制度和度分秒都能输入，一律按 WGS-84 处理）。
- **离线**：用离线包里的 SQLite 地名索引。
- **在线**：经后端代理访问 Photon（先用公共实例，以后自托管）；在大陆补充天地图地名搜索。
- **排序**：维护一张山名别名表（例如 泰山 → 玉皇顶），按重要度和距离排序。

### 2.11 队伍

[决定：队伍位置共享的上报与耗电策略](https://github.com/zibyn/stars-outdoor/issues/23)，另见 `CONTEXT.md` 中的队伍相关术语。

- **组建**：**发起人** 创建 **队伍** 并生成 4 位数字码，其他人输入这个码加入（类似微信面对面建群）。使用队伍需要手机号登录。
- **生命周期**：
  - 成员可以 **停止共享**，此时仍留在对话里。
  - 成员可以 **退出队伍**，同时离开 **队伍对话**。
  - 发起人可以 **结束行程**，所有人的位置共享一起停止，对话保留。
- **位置上报**：
  - 移动时，每 30 s 或每移动 50 m 上报一次，以先到者为准。
  - 静止时，每 3 min 发一次心跳。
  - 电量 < 20% 时改为每 2 min；电量 < 10% 时改为每 5 min，并提示一次。
  - "省电模式"开关打开后，固定每 2 min 上报。
  - 以上只影响给队友的上报频率，不影响自己的记录精度。
- **断网**：本地缓存位置；恢复网络后先报最新位置，再补传抽稀后的轨迹（每 2 min 一点）。
- **队友显示**：
  - 彩色圆点加头像字母，旁边标"x 分钟前"。
  - 超过 5 min 没更新：半透明；超过 30 min：**失联**，显示为灰色加虚线圈。
  - 列表里显示直线距离、方位和剩余电量。
  - 显示 **尾迹**（可在图层里关闭）。
- **队伍对话**：
  - 以半屏抽屉打开，上半部分仍能看到地图；可以上拉成全屏。
  - 支持文字、位置、图片消息。点击位置消息，地图定位过去。
- **一键求助**：长按"求助"，向全队发出高优先级消息，附带位置和电量；队友手机强制震动并响铃。界面写明"仅通知队友，不会联系救援"。
- **推送**：不使用厂商推送。队伍活跃期间，靠前台服务 + WebSocket 在本地弹通知；有 GMS 的设备另外接 FCM。App 被杀后，下次打开时拉取未读。

### 2.12 账号与同步

[决定：后端选型](https://github.com/zibyn/stars-outdoor/issues/10)、[决定：离线记录与云同步规则](https://github.com/zibyn/stars-outdoor/issues/26)

- **登录**：只有两个入口，一是使用队伍功能，二是主动开启同步。使用阿里云号码认证 · 短信认证，**仅支持 +86 号码**。
- **未登录**：数据只存在本机。
- **第一次开启同步**：把未登录期间的本地数据全部上传到该账号。
- **退出登录**：保留本地数据，停止同步。
- **同步范围**：轨迹（含全部轨迹点）、标注（含照片）。不同步离线地图文件和 App 设置。
- **冲突处理**：以属性为单位，按服务器记录的修改时间，最后写入的覆盖前面的。删除用删除标记同步。
- **同步时机**：打开 App、结束一段记录、修改数据之后（稍作延迟再同步）。照片默认只在 Wi-Fi 下上传。
- **配额**：轨迹不设上限；照片每人 ≤ 1 GB，超出后只保存在本地。
- **注销账号**：删除服务器上该用户的全部数据（轨迹、标注、照片、公开轨迹、对话消息，消息显示为"已注销用户"）。本地数据保留。

### 2.13 分发与更新

[决定：分发渠道与应用内更新](https://github.com/zibyn/stars-outdoor/issues/24)

- **发布渠道**：GitHub Release。
- **签名**：签名密钥自己保管，并做好异地备份（将来上架 Google Play 时沿用同一把密钥）。
- **应用内更新**：
  - 每天最多检查一次 GitHub Release。
  - 有新版本时 **不弹窗**，只在"设置"上显示小红点。
  - 下载后校验 SHA-256，再调起系统安装器。
- **版本兼容**：服务端下发"最低支持版本"。客户端低于这个版本时，**只限制联网功能**（队伍、同步、天气），离线功能照常可用。
- **风险**：GitHub 的下载在大陆可能不稳定。如果内测用户反馈下载困难，再把 APK 同步一份到 OSS 香港。

## 3. 系统

### 3.1 客户端

- Kotlin + Jetpack / JetBrains Compose + **MapLibre Compose 0.18.x**（锁定版本；OpenGL runtime）。
- 样式使用完整的 style JSON。数据源通过 `pmtiles://file://` 读取本地文件，在线时读取远程 PMTiles 或 HTTP 瓦片。地形底图在线时由服务端 `/v1/tiles/terrain/…` 从 bucket 里的全国 PMTiles 读瓦片，画在离线包下面；山体阴影和晕渲在线只用远程、离线只用本地，避免叠两遍变暗。
- 定位同时接入 HMS 和 GMS 两套 runtime，以兼容没有 GMS 的国产手机。
- 本地数据库存放轨迹点、标注、离线包清单和同步状态。
- 可复现的 spike 工程在 `spike/offline-pmtiles` 分支，其中 `push-data.sh` 可以推送样例数据。

### 3.2 后端

[决定：后端选型](https://github.com/zibyn/stars-outdoor/issues/10)（含改用 Go 的修订）、[调研：后端语言的 GIS 生态对比](https://github.com/zibyn/stars-outdoor/issues/19)

- **部署**：香港轻量 VPS（免 ICP 备案），所有组件手动部署，不使用 BaaS。
- **单个 Go 服务**，职责如下：
  - REST API：轨迹 / 标注同步、公开轨迹、队伍、账号
  - WebSocket：队伍位置与对话，单实例内存广播，不引入 Redis
  - 天气代理：带缓存，Key 不进客户端；匿名可用，按设备限流
  - 搜索代理：Photon + 天地图
  - 离线包裁剪：用 `go-pmtiles` 从 OSS 上的大文件按范围读取，裁出小包写回 OSS 缓存，并返回下载地址
  - 公开轨迹瓦片：`ST_AsMVT`
- **数据库**：PostgreSQL + PostGIS。空间计算尽量交给 PostGIS 完成。
- **接口契约**：因为前后端语言不同、不共享代码，需要单独定义接口契约（OpenAPI）。接口带版本号，并下发最低支持的客户端版本。
- **图片**：客户端压缩（长边 1600 px，约 300 KB）后上传，存在 VPS 本地磁盘；**结束行程** 180 天后删除原图，只留缩略图。
- **备份**：每天 `pg_dump`，连同图片目录一起同步到服务器以外的地方。

### 3.3 数据管线（在开发者本机上运行，每季度一次）

[ADR 0001](../adr/0001-static-pmtiles-on-object-storage.md)、[任务：样例山区离线包体积实测](https://github.com/zibyn/stars-outdoor/issues/21)（脚本：`scripts/build-data.sh`）

1. **底图**：用 `pmtiles extract` 从 Protomaps 每日构建的全球文件中裁出中国范围（约 12 GB）。
2. **DEM**：用 `pmtiles extract` 从 Mapterhorn 全球文件中裁出中国范围，z0–11（约 9 GB）。
3. **等高线**：Copernicus GLO-30 → `gdal_contour -i 20` → `ogr2ogr -f PMTiles`（z12–14，`SIMPLIFICATION=8`）。中国全境约 8–28 GB。
4. **徒步线路**：从 Geofabrik 中国 PBF 用 osmium 抽取 `route=hiking|foot`，经 GDAL 生成 GeoJSON（每条路线关系一条线，原样保留；脚本：`scripts/osm-extract.sh`）。离线包按范围收录与之相交的完整路线，不按瓦片切开。
5. **地名索引**：由 Photon 的国家导出生成 SQLite 地名索引（中国压缩后约 24 MB）。
6. **平台轨迹**：导入香港、台湾的官方开放数据，合并为一份 GeoJSON（`scripts/build-platform.py`），每条注明来源。台湾的 KMZ 目前需手动下载。
7. **上传**：以上产物全部上传到 OSS 香港。**公开 OSM 抽取脚本与标签筛选规则**，以满足 ODbL。

整条管线只依赖 `pmtiles`、GDAL（Docker）和 osmium，不需要 tippecanoe。

### 3.4 基础设施

- **香港轻量 VPS**：Go 服务 + PostgreSQL / PostGIS + 图片存储。
- **阿里云 OSS 香港**：离线地图文件（约 30–50 GB）、裁剪缓存。
- **第三方服务**：阿里云号码认证（短信）；和风天气（主）、Open-Meteo（备）；天地图（在线底图、影像、地名）；OpenFreeMap（海外在线底图）；Photon（地名搜索）。
- **域名**：需要一个域名，供 API 和 OSS 自定义域名使用。
- **费用预警**：月费超过 ¥200 时通知开发者。**不做自动熔断。**
- **上线前**：用内网服务器和 RustFS 代替香港 VPS 和 OSS，见 [ADR 0003](../adr/0003-lan-server-and-rustfs-before-launch.md)。

## 4. 非功能

### 4.1 可靠性

- 记录不中断是红线，具体做法见 2.5。
- 离线时任何界面都不能白屏或报错。
- 客户端版本过旧时，不影响任何离线功能。

### 4.2 隐私

- 轨迹默认私有。
- 公开轨迹隐藏起点和终点各 200 m。
- 支持注销账号。
- 天气代理和搜索代理都支持匿名使用。
- 内容审核暂不做（不上架国内商店）。

### 4.3 限额

| 项目 | 限额 |
|---|---|
| 单个离线包范围 | ≤ 约 100 × 100 km |
| 每台设备每天离线下载 | ≤ 1 GB |
| 单个导入文件 | ≤ 50 MB |
| 每人云端照片 | ≤ 1 GB |
| 天气代理、搜索代理 | 按设备限流 |

### 4.4 成本

[决定：成本与可持续模式](https://github.com/zibyn/stars-outdoor/issues/13)

- 约 **¥65 / 月**（100 用户）；约 **¥300–400 / 月**（1000 用户）。
- 随用户数线性增长的只有 OSS 出流量。

### 4.5 已知的坑（spike 实测）

[任务：MapLibre Compose 离线 PMTiles 与 CJK 包体积真机验证](https://github.com/zibyn/stars-outdoor/issues/14)

1. **Protomaps 官方字形没有 CJK**（CJK 区段是空占位）。必须改用含 CJK 的字形，例如 OpenFreeMap / openmaptiles 提供的 Noto Sans。
2. **字形读取失败会静默卡住整个数据源**：同一数据源里只要有 symbol 图层的字形加载失败，这个数据源的线和面也全都不渲染，而且不报错。字形文件必须对 App 可读。
3. **表达式类型不严格会静默丢弃整个图层**。例如 `["%", ["get","ele"], 100]` 必须写成 `["to-number", ["get","ele"]]`。**CI 中必须用 MapLibre 样式校验工具检查样式。**
4. Protomaps `roads` 图层的 `kind` 取值以实际数据为准。山区道路很稀疏，写样式时要用真实数据核对过滤条件。
5. **开发前风险检查**：在一台中端 Android 真机上检查拖动、缩放、倾斜的流畅度（模拟器是软件渲染，结果不具参考性）。
