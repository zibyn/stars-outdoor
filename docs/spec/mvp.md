# 星径 MVP 规格

> 状态：定稿待评审（2026-09-27）。术语以仓库根目录 [`CONTEXT.md`](../../CONTEXT.md) 为准。
> 界面（布局、按钮、抽屉、动画、文案、图标）以 [`ux-v2.md`](ux-v2.md) 为准；本文里被它取代的地方都标了「见 ux-v2 §x」。
> 每条结论都附有对应决策工单的链接，想了解"为什么这样定"就去翻工单；全部决策的索引见 [Wayfinder 地图](https://github.com/zibyn/stars-outdoor/issues/1)。

## 1. 概述

### 1.1 目标

一个 **无广告、打开即用** 的户外地图 Android App。主要服务中国大陆徒步者，同时能用来规划海外经典线路。核心价值：
- 离线地图（中国）
- 可靠的轨迹记录
- 临时 **队伍** 共享位置
- **天气** 与 **出行提醒**
- **周边路网**

### 1.2 平台与分发

- Android 优先，基于 MapLibre Compose（锁定 0.18.x），架构上为 KMP / iOS 保留余地。
- 第一版只通过 **GitHub Release** 发布 APK，不上架国内应用商店，也暂不上 Google Play。App 暂不开源。

### 1.3 产品原则（可逐条验收）

[决定：交互原则与信息架构](https://github.com/zibyn/stars-outdoor/issues/8)

1. **首屏只有地图**：启动即进地图并定位；没有开屏、信息流、商城或推广位。
2. **零打扰**：没有广告、评分弹窗、"新功能介绍"弹窗；权限在第一次用到时才申请。
3. **免登录**：地图、标注、轨迹、离线地图都不需要账号。只有 **队伍** 和云同步需要登录。
4. **离线优先**：没网时任何界面都不白屏、不报错，最多提示"离线中"。
5. **记录可靠**：切后台、锁屏、没网都不能中断轨迹记录（可信度红线）。
6. **戴手套可用**：关键按钮 ≥ 56dp，放在下半屏拇指区。
7. **数据归用户**：轨迹默认私有，界面明示；导入导出用标准格式，导出不丢标注。

### 1.4 公开承诺（写在"关于"页）

[决定：成本与可持续模式](https://github.com/zibyn/stars-outdoor/issues/13)

- **永不放广告。**
- **核心功能永久免费**：地图、离线地图（中国）、轨迹记录与导入导出、标注、队伍、天气与出行提醒、周边路网。
- 将来如果收费，只针对新增、且有明确额外成本的功能（如海外离线地图、高清卫星图）。维持方式为免费 + 自愿捐赠，捐赠不解锁任何功能。

### 1.5 不在 MVP 范围

快速匹配组队、AI 出行建议、iOS 正式版、海外离线地图、国内应用商店上架、Google Play / 官网下载页 / F-Droid、长期固定群组、海外手机号登录、个人配速自动校准、真 3D 地形、路线规划 / 到出口的导航、手表自动同步与表端显示（MVP 之后先做佳明 Connect IQ 数据栏，见 [ADR 0006](../adr/0006-watch-integration-files-first-then-garmin-data-field.md)）、心率步频等运动数据的保存。

## 2. 功能

### 2.1 主界面与信息架构

[决定：交互原则与信息架构](https://github.com/zibyn/stars-outdoor/issues/8)、[原型：主界面可点击草图](https://github.com/zibyn/stars-outdoor/issues/16)（原型：`prototype/main-screen` 分支）

交互模式、首屏布局、按钮和抽屉 / 整页的分工以 [ux-v2](ux-v2.md) 为准（取代原来的四角布局、「常驻按钮 ≤ 4」、菜单抽屉和"没有底部 Tab 栏"，见 ux-v2 §10.1）。要点：

- **两种状态**：不记录时是 **规划状态**（顶部搜索和图层，底部入口栏 我的轨迹 / 队伍 / 开始 / 离线地图 / 设置），记录中是 **活动状态**（顶部大字数据，底部 暂停 / 标注 两个大键）。见 ux-v2 §2、§3。
- **队伍入口**：底栏常驻，显示「队伍 N」（共享中、有位置的人数，含自己）和未读小红点，点开是全屏队伍页。见 ux-v2 §3.1、§4.4。
- **定位与指南针**、**标注**：见 ux-v2 §3.5、§9.1。
- **我的轨迹**：整页，分「轨迹 / 标注」两个标签；搜索、排序（默认最近）、导入；每条显示缩略图、距离、爬升、日期，以及私有 / 公开 / 计划状态。
- **长按地图**：底部小抽屉，提供 添加标注 / 测距 / 复制坐标 / 分享坐标（发给救援人员）/ 下载这附近。见 ux-v2 §4.1。
- **天气入口**：顶部栏图层左边的圆形图标按钮（这小时有雷阵雨显示雷雨图标，有降水显示雨图标，其余显示通用天气图标），未来 12 小时有 **出行提醒** 时加小红点；点开天气整页（§2.9）。

### 2.2 地图与图层

[决定：地图数据源与离线地图方案](https://github.com/zibyn/stars-outdoor/issues/9)、[调研：MapLibre Compose 3D 地形可行性](https://github.com/zibyn/stars-outdoor/issues/17)

**底图**用三张卡片切换：

| 卡片 | 国内 | 海外 | 离线 |
|---|---|---|---|
| **地形**（默认） | 自托管 Protomaps 矢量底图 + 山体阴影 + 分层设色 + 等高线 | OpenFreeMap 在线底图（MVP 不叠加山体阴影和等高线） | ✅（仅中国） |
| **卫星** | 天地图影像 | 天地图全球影像，注明"海外影像精度有限" | ⚠️ 仅已缓存区域 |
| **标准** | 天地图矢量 | OpenFreeMap | ⚠️ 仅已缓存区域 |

- **图层开关**：等高线、山体阴影、3D 地形（2.5D）、周边路网、队伍成员。另有「我的轨迹 · 已叠加 n 条」一组，管理 **叠加**（见 ux-v2 §9.2）。
- **等高线**：等距 20 m，计曲线 100 m。z12 只显示计曲线，z13 起显示全部；计曲线标注高度。
- **3D**：做 **2.5D**，即倾斜视角（最大 60°）+ 山体阴影 + 分层设色。真 3D 地形的引擎能力尚未合入，不做。进入方式：双指下拖，或打开图层里的"3D 地形"开关。
- **坐标系**：全链路 WGS-84（天地图 CGCS2000 视同 WGS-84），不接入任何 GCJ-02 / BD-09 图源。
- **署名**：地图上显示"© OpenStreetMap contributors"等所需署名。

### 2.3 离线地图

[决定：地图数据源与离线地图方案](https://github.com/zibyn/stars-outdoor/issues/9)、[任务：样例山区离线包体积实测](https://github.com/zibyn/stars-outdoor/issues/21)

- **范围**：只覆盖中国。对海外区域请求离线时提示"该地区暂不支持离线"。
- **下载方式**：在轨迹详情里"沿此轨迹下载"（按缓冲带）；或"下载这附近"：以长按选中的点、搜索结果或标注为中心，固定约 20 × 20 km，下载前告诉用户大约多大。不支持用户自己框选范围；早期按视野下载的包照常可用、可更新，但不能再新建（[决定：规划状态与活动状态的按钮清单、位置和展开方式](https://github.com/zibyn/stars-outdoor/issues/73)）。
- **包内容**：
  - 底图 PMTiles
  - DEM PMTiles（z0–11，用于山体阴影和分层设色）
  - 等高线 PMTiles（z12–14，z15 由引擎放大显示）
  - 徒步线路 GeoJSON（每条完整保留，供"经过这里的轨迹"保存或设为参考轨迹）
  - 该区域的 SQLite 地名索引
  - 该区域 **公开轨迹** 的快照
- **体积参考**：50 km 见方的山区约 20–25 MB。
- **限额**：单个包的范围 ≤ 约 100 × 100 km（匿名可用）。
- **字形**：包含 CJK 的 Noto Sans Regular 字形约 34 MB，属于一次性资源，不放进各个区域包。
- **管理**：在底栏"离线地图"整页（见 ux-v2 §4.1）查看占用空间、删除、更新。服务端有新版本时显示"可更新"标记，不弹窗。
- **用户导入**：可以导入自己的 MBTiles / PMTiles 文件（"离线地图 → 导入离线地图文件"，见 ux-v2 §6.5）。
- **地图缓存**：和离线包是两个场景。在线时看过的瓦片（底图、卫星、周边路网）由 MapLibre 自动缓存，离线时尽力显示，过期的也照用；卫星、标准卡片标"离线仅显示已缓存区域"；离线时另有状态条「卫星图离线用不了 · 切到地形」（见 ux-v2 §3.6）。不做主动"缓存此区域"（那就是离线包；批量拉天地图也有许可问题，见 #9）。
  - "设置"里一行：已用多少 MB（缓存库文件大小）· 上限 256 MB / 1 GB / 4 GB（默认 1 GB）· 清除。
  - 放在系统缓存目录，存储不足时可能被系统清掉；不按区域列出，也不在地图上画覆盖范围。

### 2.4 标注

- **一键标注当前位置** 是主方式，记录中、暂停中、不记录时都能用；定位不够新或不够准时先等定位。规则见 ux-v2 §9.1。名称和照片可以事后补。语音备注不做。
- 长按地图添加 **标注** 是次要方式；另有屏幕中心十字「在地图上选」。
- 标注可附文字和照片。导入文件中的航点会成为这条轨迹下的标注，随轨迹一起删除，不列在「标注」标签里（轨迹显示在地图上时一起显示）。
- **标注组**（[#121](https://github.com/zibyn/stars-outdoor/issues/121)）：导入只有标注、没有轨迹的文件时自动建一个，用户也可以自建，把自己的标注放进去；组名同一账号下不重复；整组叠加或删除，组会同步。

### 2.5 轨迹记录

[决定：离线记录与云同步规则](https://github.com/zibyn/stars-outdoor/issues/26)、[决定：队伍位置共享的上报与耗电策略](https://github.com/zibyn/stars-outdoor/issues/23)

- **采样**：每 5 s 或每移动 10 m 取一个点，以先到者为准。
- **前台服务**：与队伍位置共享合并为同一个前台服务。通知栏只常驻一条通知，带「停止共享」「结束」按钮（文案见 ux-v2 §6.5）。
- **可靠性**：
  - 每个点采到后立即写入本地数据库。
  - 进程被杀或崩溃后，下次打开时提示继续记录或结束并保存（文案见 ux-v2 §6.5）。
  - 支持暂停和继续，一条轨迹可以由多段组成。
  - 按手机品牌（小米、华为、OPPO、vivo 等）引导关闭电池优化。不在第一次开始记录时弹出，改在轨迹详情（设为参考或沿线下载之后）和设置页里，见 ux-v2 §4.2、§8。
- **不可变**：结束记录后轨迹点不可修改，之后只能改属性（名称、描述、公开状态、坐标纠偏）；截取、合并都生成新的轨迹。轨迹可以删除。
- **轨迹详情**：轨迹铺满地图，底部抽屉最低收到窄条（统计 + 我在轨迹上的位置），不会被拉没；上拉是海拔剖面、"设为参考""叠加到地图"、沿线离线地图等操作；内容和顺序见 ux-v2 §4.2。不含天气。缩略图和海拔剖面上都有 **里程标注**，样式与地图上相同，可切换正向 / 反向（见 2.7）。

### 2.6 导入与导出

[决定：轨迹导入导出格式与互通](https://github.com/zibyn/stars-outdoor/issues/22)

- **导入格式**：GPX 1.1、KML / KMZ（包括奥维导出的 `.ovkml` / `.ovkmz`）、FIT（使用 Garmin 官方 Java SDK）、GeoJSON、PLT。不支持 TCX。**全部在客户端解析。**
- **入口**：
  - 我的轨迹 → 导入轨迹文件（见 ux-v2 §6.5）
  - 系统分享和"用其他应用打开"，例如从微信、QQ 收到的文件
- **手表**：MVP 不做自动同步。用户从手表的 App 导出 FIT / GPX 后照常导入；导入 FIT 时，从文件头读出厂商和型号作为来源（"来自 佳明 fēnix 7"），GPX 不标。只取轨迹与海拔，不自动去重；手机也录了，就两条都留。路线进表用 GPX 导出（[ADR 0006](../adr/0006-watch-integration-files-first-then-garmin-data-field.md)）。
- **多要素**：一个文件含多条轨迹时，先让用户勾选再拆开导入；GPX 的 `rte` 导入为"计划"轨迹。
- **坐标纠偏**：默认按 WGS-84 解析。轨迹详情里有"坐标纠偏"开关，可选 GCJ-02（高德、腾讯）或 BD-09（百度）（界面文案见 ux-v2 §6.5），实时预览效果，只对中国境内的坐标生效。
- **大小**：单个文件 ≤ 50 MB；原始点全部保留，显示时抽稀。
- **导出**：
  - 默认 GPX 1.1（含时间、海拔，以及标注的名称、描述、时间）；也可以导出 KML。
  - 标注带照片时，打包成 `.zip`（GPX + 照片文件夹）。
  - 通过系统分享面板发送。

### 2.7 循迹、沿轨里程与偏离提醒

[Wayfinder: 沿轨里程、队伍轨迹与手表对接](https://github.com/zibyn/stars-outdoor/issues/81)：[原型：沿轨里程与里程标注的显示方式](https://github.com/zibyn/stars-outdoor/issues/83)（原型：`prototype/distance-along-track` 分支）、[决定：活动状态顶部数据加入沿轨里程](https://github.com/zibyn/stars-outdoor/issues/85)

- 选一条轨迹设为 **参考轨迹**。不做逐向导航，不做路线规划，也不做路网吸附。
- **起算点**：参考轨迹带一个本机的起算点设置，不改轨迹本身（轨迹仍不可变，见 2.5），也不同步。可选正向 / 反向；环线还可以换起点（「在轨迹上选」：在地图上点一下轨迹上的位置，见 ux-v2 §4.3），也能恢复原起点。
- **沿轨里程**：把当前位置投影到参考轨迹上，从起算点沿线量出的距离，不是直线距离，保留一位小数。
  - 往返线、交叉处同一位置有多个值时全部列出，从小到大排（"3.1 / 16.9 km"），不做推断。
  - 精度差于 50 m 时，数字和位置点置灰，并写"精度差 ±80 m"。
- **不记录时（规划状态）**：
  - App 在前台亮屏时持续定位，实时更新沿轨里程；退到后台或锁屏就停止定位，不需要前台服务。
  - 当前里程显示在搜索栏下面的 **参考轨迹条**（位置和状态见 ux-v2 §3.2）：一行大字，右侧写精度和全长，上方小字写"沿轨里程 · 正向 / 反向"。
  - 点参考轨迹条打开参考轨迹抽屉：抽屉里有海拔剖面（横轴是沿轨里程，带整公里刻度，当前位置有几个值就画几条竖线）、正向 / 反向、环线起点设置，以及"不再用作参考轨迹"。地图上的"起"点不能点。
  - 离轨迹超过 60 m 时不显示里程，改为"不在轨迹上"，并写"离轨迹 150 m"。
  - **不记录时没有偏离提醒。**
- **里程标注**：在参考轨迹上从起算点起标出整公里，样式是白底、参考轨迹色描边的圆角牌，只写数字。
  - 间隔随缩放变化：每公里 ≥ 45 px 时每 1 km 标一个，≥ 12 px 时每 5 km，否则每 10 km。
  - 往返线上同一处的两个标注合成一个（"3 / 14"）。
  - 轨迹上画方向小箭头，起点和终点标"起""终"，随正向 / 反向和起点设置变化。
  - 只画在参考轨迹上，轨迹详情预览也有；**叠加** 和周边路网不画。
- **记录时（活动状态）**：
  - 顶部大字数据第一页：有参考轨迹时，上面一整行是"沿轨 km"（多值全列），下面三格是 已走 km / 用时 / 爬升，海拔移到第二页；没有参考轨迹时，这一行不出现，第一页是四格 已走 km / 用时 / 爬升 / 海拔。
  - 第二页：km 用时 / 剩余 km / 海拔 / 电量。"剩余"是全长减沿轨里程，按本机的起算点设置算；有多个值或偏离时显示"—"。没有参考轨迹时，这两格换成 均速 / 最高海拔。不估算到达时间（ADR 0009）。
  - 偏离超过阈值（默认 50 m）时触发 **偏离提醒**（震动 + 通知），同时沿轨那一行显示"偏离 150 m"，用警示色。

### 2.8 周边路网

[决定：周边路网数据方案](https://github.com/zibyn/stars-outdoor/issues/12)、[ADR 0002](../adr/0002-ugc-separate-from-osm.md)

周边路网由 **两个独立图层** 组成，互不合并，在图层抽屉里用一个"周边路网"开关统一控制：

1. **OSM 路径与徒步线路**
   - 山路和小径复用底图要素，打开开关时画成淡色细线，位于用户轨迹之下（见 ux-v2 §3.8）。
   - **徒步线路**（`route=hiking|foot`）单独做成 GeoJSON，随底图更新，并进入离线包。
2. **公开轨迹**
   - 数据来自 PostGIS。z11 起在线显示，离线时使用包内快照和地图缓存里的瓦片（两处都有时颜色叠深，可以接受）。
   - z12 以上画成细的半透明线，重叠越多颜色越深。

**交互**：点击地图弹出"经过这里的轨迹"列表，可以把某条设为参考轨迹，或保存到我的轨迹（保存后按钮变「已保存 · 查看」，见 ux-v2 §6.5）。离线时只列出离线包里的线；地图缓存里的线看得到但列不出，提示"离线中：只能列出离线包内的轨迹"。下架或撤回公开的轨迹，离线时可能仍从快照或缓存显示，直到联网刷新或清除缓存。

**公开规则**：
- 轨迹默认私有，需要逐条公开。
- 公开时自动隐藏起点和终点各 200 m 的范围。
- 可以随时撤回公开；删除轨迹、注销账号同样撤下。别人已保存的副本不收回（ADR 0007）。
- 查看别人的公开轨迹不需要登录，自己公开轨迹需要登录。

**应急**：只做可视化，可以配合测距量出到道路或村庄的直线距离。不做到出口的路线规划。

### 2.9 天气与出行提醒

[决定：天气平台与出行提醒规则](https://github.com/zibyn/stars-outdoor/issues/11)

- **数据源**：主源是和风天气（1 km、逐小时、最长 240 h）加上它的预警接口；备用源是 Open-Meteo。**所有请求都经后端代理**，客户端不直连天气平台。
- **按地点，不按时刻**（ADR 0009、0010、0011）：天气是某个地点的数据，不估算到达时间，没有配速档和出发时间。地点是我的位置（顶部栏的天气按钮）、长按地图「这里的天气」，或一条轨迹沿线（轨迹详情顶栏的天气按钮）。从哪里进就看哪里，天气页里不再切换地点。
- **沿途天气**：起点、约每 5 km 一处（最多共 8 处）、最高点、终点，同一 1 km 网格只取一处；海拔剖面上标出这些地点，选中的那天有雷雨、强降水或大风的标红，地点按钮上写那天的最高 / 最低气温；点哪处看哪处的预报。
- **内容**：未来 7 天（和风逐小时最长 168 h）逐小时的天气（晴、多云、阴、雾、雨、雪、雷阵雨）、气温、体感、降水、风向和阵风，日出日落，官方预警。页面从上到下：现在、7 天日期条（每天的图标、最高 / 最低、降水量，有雷雨、强降水或大风加红点；低温在高处几乎天天有，只在数字上标红，点哪天看哪天）、那天的气象图（横向滑动，气温曲线、体感、降水柱、风向箭头和阵风对齐在同一时间轴上，夜间时段加底色）。超过下面阈值的数值标红，怎么走由用户判断。
- **出行提醒**（每种只说第一次出现的那个小时）：

| 提醒 | 触发 |
|---|---|
| 雷暴 | 天气现象为雷阵雨类，或区域有雷电 / 强对流预警 |
| 强降水 | 小时降水 ≥ 8 mm |
| 大风 | 阵风 ≥ 17.2 m/s |
| 低温 | 体感温度 ≤ 0°C |
| 官方预警 | 途经区域的任何官方预警原样转发 |

- **海拔修正**：温度按 −0.65°C / 100 m 修正（我的 GPS 海拔与网格海拔之差；长按的点没有海拔，不修正；轨迹沿线用轨迹点的海拔）。
- **离线**：我的位置的最近一次预报存在本机；离线时显示"预报更新于 X 小时前"，超过 12 h 置灰。长按点和沿途天气不缓存。
- **刷新**：App 在前台时，整点或移动约 5 km 后重新获取我的位置的天气。
- **记录时的提醒**：记录期间只要有网，每 2 h 查一次当前位置未来 3 小时，发现本次记录还没提醒过的风险就发本地通知；还没定位就 5 分钟后再试。

### 2.10 搜索

[调研：地名/山峰搜索数据源（含离线）](https://github.com/zibyn/stars-outdoor/issues/18)

- **入口**：规划状态的顶部搜索栏，打开搜索整页（见 ux-v2 §3.1）。
- **搜索内容**：地名、山峰、景点、坐标（十进制度和度分秒都能输入，一律按 WGS-84 处理）。
- **离线**：用离线包里的 SQLite 地名索引。
- **在线**：经后端代理访问 Photon（先用公共实例，以后自托管）；在大陆补充天地图地名搜索。
- **排序**：维护一张山名别名表（例如 泰山 → 玉皇顶），按重要度和距离排序。
- **来源说明**（OpenStreetMap、Photon、天地图）放在「关于」页。

### 2.11 队伍

[决定：队伍位置共享的上报与耗电策略](https://github.com/zibyn/stars-outdoor/issues/23)，另见 `CONTEXT.md` 中的队伍相关术语。

- **组建**：**发起人** 创建 **队伍** 并生成 4 位数字码，其他人输入这个码加入（类似微信面对面建群）。使用队伍需要手机号登录。
- **生命周期**：
  - 成员可以 **停止共享**，此时仍留在对话里。
  - 成员可以 **退出队伍**，同时离开 **队伍对话**。
  - 发起人可以 **结束行程**，所有人的位置共享一起停止，对话保留。
- **位置上报**：
  - 移动时，每 30 s 或每移动 50 m 上报一次，以先到者为准。
  - 静止时，每 3 min 发一次心跳。
  - 电量 < 20% 时改为每 2 min；电量 < 10% 时改为每 5 min。电量提示见 ux-v2 §3.6（低于 20% 就显示状态条，不论是否在队伍里）。
  - "省电模式"开关打开后，固定每 2 min 上报。
  - 以上只影响给队友的上报频率，不影响自己的记录精度。
- **断网**：本地缓存位置；恢复网络后先报最新位置，再补传抽稀后的轨迹（每 2 min 一点）。
- **队友显示**：
  - 彩色圆点加头像字母；停止共享的留灰色空心点。位置很久没更新不另标状态，只在队友小抽屉和成员详情里显示最后上报「x 分钟前」。见 ux-v2 §4.5。
  - 队伍信息页的成员列表，点成员显示最后上报「x 分钟前」、直线距离、方位、电量和沿轨里程。见 ux-v2 §4.4。
  - 显示 **尾迹**（可在图层里关闭）。
- **队伍对话**：
  - 就是全屏队伍页（形态同微信群），页内不嵌地图。见 ux-v2 §4.4。
  - 支持文字、位置、图片消息；「发我的位置」只发当前位置。点位置消息，回到主地图并定位到该点。
  - 结束行程后对话照常可看、可发。
  - 位置消息自动带上发送者的沿轨里程；消息格式（「位置 · 沿轨 7.3 km · 距你 1.2 km · 点这里看」）和省略规则见 ux-v2 §6.5。分享坐标（发给队外）不带里程。
- **不做一键求助和失联**：已移除（[#124](https://github.com/zibyn/stars-outdoor/issues/124)），需要求助时在队伍对话里发位置。消息不带电量。
- **队伍轨迹**（[决定：队伍轨迹的指定、下发与更换](https://github.com/zibyn/stars-outdoor/issues/84)）：
  - **发起人** 从自己的"我的轨迹"里选一条（含计划轨迹；公开轨迹先保存再选），连同起算点作为快照上传给队伍。队伍可以没有队伍轨迹；发起人可以随时更换、改起算点或取消。行程结束后，服务端删除快照。
  - 成员收到后自动设为参考轨迹，底部提示条可以"撤销"。这条轨迹同时进入成员的"我的轨迹"，和导入的一样，可以公开、导出，不加限制。私有轨迹也可以指定，不隐藏起点和终点的 200 m。
  - 加入队伍时一并下载，存在本机，离线也能用。离线的成员重新连上后，拿到当前的那一条。下载完成前显示"正在获取队伍轨迹"。
  - 更换、改起算点、取消时，队伍对话自动发一条系统消息（"发起人把队伍轨迹换成 武功山环线（反向）"）。已经在本机改用别的参考轨迹的成员不会被换回来。
  - 成员详情里显示队友的沿轨里程，一律按队伍轨迹算，多值全部列出。两人都在队伍轨迹上、而且各自只有一个值时，才显示领先 / 落后（按队伍轨迹方向，里程大的算领先；写法「7.3 km · 领先 0.8」，见 ux-v2 §4.4）；不在轨迹上的显示"不在队伍轨迹上"。由各客户端用收到的位置自己算。
- **由位置共享生成轨迹**：本次行程中没有记录轨迹的成员，在发起人 **结束行程** 或自己 **退出队伍** 时，由本机用自己上报过的位置生成一条轨迹，存进"我的轨迹"，来源标为"由队伍位置共享生成"。一人一条，只用本人的位置，规则和普通轨迹相同。点比较稀，停止共享的时段断开成多段（位置久未更新不断开）；上报间隔不因此改变。记录过的成员不生成。
- **推送**：不使用厂商推送。队伍活跃期间，靠前台服务 + WebSocket 在本地弹通知；有 GMS 的设备另外接 FCM。App 被杀后，下次打开时拉取未读。

### 2.12 账号与同步

[决定：后端选型](https://github.com/zibyn/stars-outdoor/issues/10)、[决定：离线记录与云同步规则](https://github.com/zibyn/stars-outdoor/issues/26)

- **登录**：只有两个入口，一是使用队伍功能，二是主动开启同步。使用阿里云号码认证 · 短信认证，**仅支持 +86 号码**。
- **未登录**：数据只存在本机。
- **第一次开启同步**：把未登录期间的本地数据全部上传到该账号。
- **退出登录**：保留本地数据，停止同步。
- **同步范围**：轨迹（含全部轨迹点）、标注（含照片）、标注组（叠加开关不同步）。不同步离线地图文件和 App 设置。
- **冲突处理**：以属性为单位，按服务器记录的修改时间，最后写入的覆盖前面的。删除用删除标记同步。
- **界面**：设置里「同步（开关）· 上次同步 14:05」；同步失败的状态条只在规划状态显示（见 ux-v2 §3.6、§6.5）。
- **同步时机**：打开 App、结束一段记录、修改数据之后（稍作延迟再同步）。照片默认只在 Wi-Fi 下上传。
- **配额**：轨迹不设上限；照片每人 ≤ 1 GB，超出后只保存在本地。
- **注销账号**：删除服务器上该用户的全部数据（轨迹、标注、照片、公开轨迹、对话消息，消息显示为"已注销用户"）。本地数据保留。

[决定：分发渠道与应用内更新](https://github.com/zibyn/stars-outdoor/issues/24)

- **发布渠道**：GitHub Release。
- **签名**：签名密钥自己保管，并做好异地备份（将来上架 Google Play 时沿用同一把密钥）。

## 3. 系统

### 3.1 客户端

- Kotlin + Jetpack / JetBrains Compose + **MapLibre Compose 0.18.x**（锁定版本；OpenGL runtime）。
- 样式使用完整的 style JSON。数据源通过 `pmtiles://file://` 读取本地文件，在线时读取远程 PMTiles 或 HTTP 瓦片。地形底图在线时由服务端 `/v1/tiles/terrain/…` 从 bucket 里的全国 PMTiles 读瓦片，画在离线包下面；山体阴影和晕渲在线只用远程、离线只用本地，避免叠两遍变暗。
- 定位同时接入 HMS 和 GMS 两套 runtime，以兼容没有 GMS 的国产手机。
- 本地数据库存放轨迹点、标注、离线包清单和同步状态。
- 可复现的 spike 工程在 `spike/offline-pmtiles` 分支，其中 `push-data.sh` 可以推送样例数据。

### 3.2 后端

[决定：后端选型](https://github.com/zibyn/stars-outdoor/issues/10)（含改用 Go 的修订）、[调研：后端语言的 GIS 生态对比](https://github.com/zibyn/stars-outdoor/issues/19)

- **部署**：香港轻量 VPS（免 ICP 备案），所有组件手动部署，不使用 BaaS。
- **单个 Go 服务**，职责如下：
  - REST API：轨迹 / 标注同步、公开轨迹、队伍、账号
  - WebSocket：队伍位置与对话，单实例内存广播，不引入 Redis
  - 天气代理：带缓存，Key 不进客户端；匿名可用，按设备限流
  - 搜索代理：Photon + 天地图
  - 离线包裁剪：用 `go-pmtiles` 从 OSS 上的大文件按范围读取，裁出小包写回 OSS 缓存，并返回下载地址
  - 公开轨迹瓦片：`ST_AsMVT`
- **数据库**：PostgreSQL + PostGIS。空间计算尽量交给 PostGIS 完成。
- **接口契约**：因为前后端语言不同、不共享代码，需要单独定义接口契约（OpenAPI）。接口带版本号，并下发最低支持的客户端版本。
- **图片**：客户端压缩（长边 1600 px，约 300 KB）后上传，存在 VPS 本地磁盘；**结束行程** 180 天后删除原图，只留缩略图。
- **备份**：每天 `pg_dump`，连同图片目录一起同步到服务器以外的地方。

### 3.3 数据管线（在开发者本机上运行，每季度一次）

[ADR 0001](../adr/0001-static-pmtiles-on-object-storage.md)、[任务：样例山区离线包体积实测](https://github.com/zibyn/stars-outdoor/issues/21)（脚本：`scripts/build-data.sh`）

1. **底图**：用 `pmtiles extract` 从 Protomaps 每日构建的全球文件中裁出中国范围（约 12 GB）。
2. **DEM**：用 `pmtiles extract` 从 Mapterhorn 全球文件中裁出中国范围，z0–11（约 9 GB）。
3. **等高线**：Copernicus GLO-30 → `gdal_contour -i 20` → `tippecanoe`（z12–14）。中国全境约 8–28 GB。
4. **徒步线路**：从 Geofabrik 中国 PBF 用 osmium 抽取 `route=hiking|foot`，经 GDAL 生成 GeoJSON（每条路线关系一条线，原样保留；脚本：`scripts/osm-extract.sh`）。离线包按范围收录与之相交的完整路线，不按瓦片切开。
5. **地名索引**：由 Photon 的国家导出生成 SQLite 地名索引（中国压缩后约 24 MB）。
6. **上传**：以上产物全部上传到 OSS 香港。**公开 OSM 抽取脚本与标签筛选规则**，以满足 ODbL。

整条管线只依赖 `pmtiles`、GDAL（Docker）和 osmium，不需要 tippecanoe。

### 3.4 基础设施

- **香港轻量 VPS**：Go 服务 + PostgreSQL / PostGIS + 图片存储。
- **阿里云 OSS 香港**：离线地图文件（约 30–50 GB）、裁剪缓存。
- **第三方服务**：阿里云号码认证（短信）；和风天气（主）、Open-Meteo（备）；天地图（在线底图、影像、地名）；OpenFreeMap（海外在线底图）；Photon（地名搜索）。
- **域名**：需要一个域名，供 API 和 OSS 自定义域名使用。
- **费用预警**：月费超过 ¥200 时通知开发者。**不做自动熔断。**
- **上线前**：用内网服务器和 RustFS 代替香港 VPS 和 OSS，见 [ADR 0003](../adr/0003-lan-server-and-rustfs-before-launch.md)。

## 4. 非功能

### 4.1 可靠性

- 记录不中断是红线，具体做法见 2.5。
- 离线时任何界面都不能白屏或报错。
- 客户端版本过旧时，不影响任何离线功能。

### 4.2 隐私

- 轨迹默认私有。
- 公开轨迹隐藏起点和终点各 200 m。
- 支持注销账号。
- 天气代理和搜索代理都支持匿名使用。
- 内容审核暂不做（不上架国内商店）。

### 4.3 限额

| 项目 | 限额 |
|---|---|
| 单个离线包范围 | ≤ 约 100 × 100 km |
| 单个导入文件 | ≤ 50 MB |
| 每人云端照片 | ≤ 1 GB |
| 天气代理、搜索代理 | 按设备限流 |

### 4.4 成本

[决定：成本与可持续模式](https://github.com/zibyn/stars-outdoor/issues/13)

- 约 **¥65 / 月**（100 用户）；约 **¥300–400 / 月**（1000 用户）。
- 随用户数线性增长的只有 OSS 出流量。

### 4.5 已知的坑（spike 实测）

[任务：MapLibre Compose 离线 PMTiles 与 CJK 包体积真机验证](https://github.com/zibyn/stars-outdoor/issues/14)

1. **Protomaps 官方字形没有 CJK**（CJK 区段是空占位）。必须改用含 CJK 的字形，例如 OpenFreeMap / openmaptiles 提供的 Noto Sans。
2. **字形读取失败会静默卡住整个数据源**：同一数据源里只要有 symbol 图层的字形加载失败，这个数据源的线和面也全都不渲染，而且不报错。字形文件必须对 App 可读。
3. **表达式类型不严格会静默丢弃整个图层**。例如 `["%", ["get","ele"], 100]` 必须写成 `["to-number", ["get","ele"]]`。**CI 中必须用 MapLibre 样式校验工具检查样式。**
4. Protomaps `roads` 图层的 `kind` 取值以实际数据为准。山区道路很稀疏，写样式时要用真实数据核对过滤条件。
5. **开发前风险检查**：在一台中端 Android 真机上检查拖动、缩放、倾斜的流畅度（模拟器是软件渲染，结果不具参考性）。
